# Mission format

Use this for the teaching workspace's `MISSION.md`:

```md
# Mission: {Topic}

## Why

{One to three sentences about the concrete outcome in the user's life or work.}

## Success looks like

- {A specific, observable ability}
- {Another observable ability}

## Constraints

- {Time, budget, existing knowledge, commitments, or learning preferences}

## Out of scope

- {Adjacent topics explicitly excluded by the user}
```

Keep one mission per workspace and keep it short. Prefer a concrete outcome
such as independently writing an isolated API test over "understand testing."
Ask about missing purpose rather than inventing it. Confirm mission changes
with the user, then update the document and record the reason as a learning
insight. Keep the active queue and progress in NOTES.md.
